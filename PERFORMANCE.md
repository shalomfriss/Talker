# Performance evidence

Measurements below were made on November 2, 2026 with Xcode 27A266a and an iPad Pro 11-inch (M4) iOS 27 simulator. Simulator launch and screenshot timing varied between runs, so these are diagnostics rather than device guarantees.

| Path | Measurement | Evidence |
| --- | --- | --- |
| Load a saved 1,000-word profile | 9 ms average over three iterations | `CommunicationStoreTests.testThousandWordProfileLoadPerformance` |
| Generate 30 typed-word completions from 1,000 words, before prefix filtering | 144 ms average over three iterations | `WordPredictionTests.testThousandWordTypingSuggestionsPerformance` before the prefix check |
| Same 30 completions after prefix filtering | 61 ms average over three iterations, about 58% less time | `WordPredictionTests.testThousandWordTypingSuggestionsPerformance`; all `WordPredictionTests` passed |
| Generate 30 sentence suggestions from 1,001 phrases and 5,050 history turns | 126 ms average over three Debug iterations | `SentencePredictionTests.testLargePhraseAndHistorySuggestionsPerformance`; all `SentencePredictionTests` passed |
| `OpenVoiceApp.init` through the first Speak view appearance | 0.63–1.35 seconds across three Debug launches | Temporary timestamp probe, since removed |
| Profile data setup inside `OpenVoiceApp.init` | 30–73 ms in those launches | Same temporary probe |

In one launch, `OpenVoiceApp.init` began about 2.3 seconds after the simulator launch command started. A small SwiftUI comparison app began its `App.init` about 1.9 seconds after its launch command started. These single-run comparisons do not isolate an Open Voice bottleneck before `App.init`. The temporary App Launch Instruments trace did not provide usable lifecycle samples. The paired physical iPad required a passcode before Xcode could mount its developer image, so hardware launch timing is still unmeasured.

An optimized macOS harness compiling the same `SentencePrediction.swift` source measured 30 sentence-suggestion queries against 1,001 phrases and 5,050 history turns. The three-run average fell from 148 ms to 72 ms (about 51%) after skipping word splitting for nonmatching phrases and stopping the history scan after 50 eligible turns. The result count stayed the same. This is a source-level comparison, not an iPad latency measurement; `SentencePredictionTests.testLargePhraseAndHistorySuggestionsPerformance` records the workload for simulator testing.

Speak, Expanded Typing, and the alphabet keyboard now reuse sentence suggestions from one store cache while the typed draft and prediction content are unchanged. A focused test confirms reuse and refresh after a saved phrase, draft edit, and language change. All six `SentencePredictionTests` passed on the iPad simulator; the large fixture averaged 129 ms for 30 queries in that Debug run.

A separate Time Profiler capture sampled the first Speak layout. Its largest main-thread leaf costs were Swift protocol-conformance lookup (100 ms) and a framework `find(_:key:filter:)` routine (52 ms); the largest directly attributed Open Voice view method was 4 ms. This points to initial SwiftUI/runtime setup rather than a single slow app algorithm. The capture began after `App.init`, so it cannot attribute the earlier gap.

The empty launch configuration was replaced with a static two-tone `LaunchScreen.storyboard` that matches the Speak screen's pale header and near-white body. A Release build included the compiled storyboard. Fresh iPad Air 11-inch (M3) and iPhone 17 Pro iOS 26.5 simulators showed the new surface during the app-opening animation and then rendered the Speak board. This removes the all-white first frame; it does not establish a reduction in time to the first usable communication action.

On a clean iPad Air 11-inch (M3) iOS 26.5 simulator, opening Get attention stalled the main thread for more than a minute. A two-second `sample` capture placed every main-thread sample inside `AVSpeechSynthesisVoice(language:)`; after moving voice lookup to a background cache, a second capture placed every main-thread sample inside `AVSpeechSynthesizer.speak`. Speech commands now run on a serial background queue, and the UI tracks queued utterances so automatic alert repetition waits for the previous one. The same focused UI test then passed in 19.8 seconds and could open the alert, toggle repetition, stop it, and navigate away. The simulator speech service can still fail to produce audible output while it is stalled; this change keeps the app usable during that stall.

The installed voice list used by phrase and Settings pickers is now requested off the main thread. This removes another synchronous speech-service call from view rendering. The phrase picker populates when the catalog responds; a simulator with a stuck voice service will show only its current-voice choice until then.

The board-folder voice picker uses that same on-demand catalog. Picture-message speech looks up folder voices in a cache keyed by the profile, vocabulary revision, folder assignments, and voice choices; profiles without folder voices retain the original direct path. WAV export waits at most about 1.5 seconds for selected voice identifiers to resolve off the main thread before rendering. Actual voice quality and first-use selection still need physical-device listening checks.

Typed-word and sentence suggestion caches now use a revision that changes only when their inputs change: saved phrases, spoken history, learned predictions, or quick replies. Display-setting and routine saves no longer force suggestion recalculation. Board-hint invalidation still tracks the broader vocabulary revision. The focused sentence and word prediction suites passed all 23 tests on the available iPad Pro 11-inch (M4) iOS 27 simulator, including checks that unrelated saves reuse the cached result and vocabulary or quick-reply edits refresh it. Call-audio status refreshes also publish only changed values, avoiding redundant view updates during startup and foreground transitions.

The existing 1,000-word board UI test passed on that simulator: it found the first word and composed two words within its interaction checks. XCTest first reported the word 8.46 seconds after the test began, which includes app launch, automation setup, and fixture creation; it is not a normal-user startup measurement.

Speak-board photo and video-poster thumbnails now decode and downsample on background tasks as their visible tiles appear. Until a thumbnail is ready, its button shows the existing symbol and stays usable. The board also computes recent-word highlights and label visibility once per displayed grid instead of once per tile. Two focused thumbnail tests passed, including the background decode path; the 1,000-word board interaction test and a UI test that saves a photo button and waits for its image both passed on the current iPad simulator. These checks verify behavior and remove synchronous tile decoding from the Speak path; they do not establish a measured whole-app startup speedup or photo-heavy physical-device frame rate.

The same on-demand thumbnail view now covers grouped picture-board previews, saved-phrase list rows and picture cards, and Life notebook timeline photos and picture-word editor previews. Three focused UI tests passed for grouped board selection, a photo button, and a saved photo phrase after relaunch. Two Life notebook UI tests passed for creating and reopening a moment and for picture words with speech after relaunch. Photo-heavy scrolling and first-image latency still need direct measurement on physical devices.

Routine-step pictures, weekly-plan and visual-calendar rows, reward-chart list and detail photos, and the personal picture library grid now use that on-demand view as well. Focused iPad UI tests passed for choosing a library photo in a routine and phrase, speaking and completing a weekly activity, completing a calendar event linked to a reward chart, filling and collecting a reward, and pasting a photo that appears in its saved chart. An initial multi-test run hit repeated simulator automation idle waits; a two-second sample during that delay found the app's main thread idle in the run loop. The individual reruns passed after rebooting the simulator, so that delay is not evidence of app-side photo decoding.

The remaining story reader and photo background, scene canvas and lists, lanyard card, large picture-message display, nearby picture chat, routine template and timer views, notebook detail and editor, speech-to-picture preview, and several editor previews now use the same background thumbnail view. This removes synchronous `UIImage(data:)` and uncached thumbnail decoding from feature view rendering. A two-photo story grid UI test passed on the iPad, including removing a photo; a notebook picture-word UI test passed through save and reopen. Five photo-processing tests passed, including the 320-pixel notebook picture-word bound and background captured-photo preparation. A scene UI attempt never started its runner after two minutes in Xcode's test setup, so scene behavior after this change remains unverified by that test. The current Release build installed and rendered the Speak board on the iPad Pro 11-inch (M4) iOS 27 simulator. These checks verify compilation and selected flows, not a measured scrolling frame rate or cold-start improvement.

Nearby picture-chat sends now downsample up to 100 picture tokens on background tasks to 128-pixel JPEGs at the prior 0.65 quality. The Send controls show a pending state and prevent duplicate taps, and the service checks its connection again after preparation. A typed reply stays in the field until the send succeeds. Nearby packet JSON encoding now runs in a detached task, and incoming packet decoding uses a serial background queue that preserves message order. The service checks that the same session and recipients are still connected after encoding. All eight nearby chat tests passed on the iPad simulator, including a 100-picture async packet round trip, reduced-photo packet size, encrypted two-device exchange, and sending to one or multiple connected peers; a focused rerun also checked received message order. The large packet round trip took 9 ms in that Debug test. The Release build installed, launched, and rendered the Speak board on the current iPad simulator. MultipeerConnectivity transmission still occurs on the service's main actor; physical-device latency remains unmeasured.

Personal picture-library imports and the shared Paste image action now resize and encode source data on a background task using ImageIO, with a 1,200-pixel maximum side and JPEG output. The library checks that the active profile has not changed during preparation. Five photo-processing tests passed for bounded output from data, a file, and a captured image, corrupt input, and EXIF orientation; the library persistence test and iPad UI tests for pasting a picture button and a reward photo passed. Photos imports in the item, calendar, weekly activity, reward chart, routine, scene, story, notebook, and saved-phrase editors now use the same background preparation. Files image imports in the reward chart, routine, scene, and saved-phrase editors downsample directly from the file on a background task while holding their security scope, avoiding a full-size data copy. The saved-phrase photo UI flow passed through import and relaunch, and the reward-photo UI flow passed on an isolated rerun. Its first run failed at a simulator keyboard-focus event before image selection. Notebook picture-word resizing now runs in a background task, and Save waits for it to finish. Camera capture now prepares its bounded JPEG on a background task while keeping the picker open until the result is ready. The synthetic captured-photo test passed on the iPad simulator; completing a real capture and measuring latency still require a physical device.

After the Release install for this change, one `simctl launch` took 8.6 seconds and an immediate screenshot caught a black transition; the Speak board rendered shortly afterward. A warm relaunch on the same simulator returned in 0.75 seconds and a screenshot command started immediately afterward captured the board during its opening animation. These command and screenshot timings include simulator service and animation work, so they do not measure first usable speech or establish a cold-start regression.

After moving editor photo imports to background ImageIO preparation, the Release build passed with reduced Xcode build parallelism. It installed and launched on the available iPad Pro 11-inch (M4) iOS 27 simulator. The immediate screenshot again caught a black simulator opening transition; the following screenshot showed the usable Speak board. No new first-action latency measurement was taken.

Optional communication-use recording returns before creating a record when disabled or in a private conversation. When enabled, records are capped at 1,000 per profile; imported records stop processing at that limit, and the review screen shows only the latest 50 entries. The profile writer coalesces the recording save with the message save made by the same picture-button selection. Focused tests cover opt-in behavior, privacy, profile and backup persistence, CSV escaping, and the cap.

After the catalog was loaded only when a phrase screen opens, the focused language and speech-engine unit tests passed on the iPad Air simulator. The attention UI test also passed in 16.9 seconds with the final queued speech path. The final Release build passed with a generic iOS Simulator destination.

Personal picture library images are stored in a separate per-profile file and loaded on demand in the library screen. Routine profile saves contain an empty library field, so adding pictures does not make the startup profile JSON grow with library images. Library cells and small editor previews use the existing bounded, downsampled thumbnail cache. The starter gallery uses existing vocabulary and renders an image only when selected. A focused test verified the lazy load, profile separation, backup inclusion, older-backup import, library cleanup when a profile is deleted, and retained button photo after library deletion. This establishes the data-path behavior; hardware startup timing with a large library is still unmeasured.

Life-notebook photos, short videos, picture-word images, and conversation turns use a separate per-profile file and load when the notebook opens. Routine profile snapshots carry an empty notebook field; explicit backups read the posts from disk. The notebook is capped at 100 posts, 2 MB per photo, 8 MB per video, eight picture words per post with 512 KB per image, 40 short turns per post, 20 MB total photo data, and 30 MB total media. Picture-word sources are resized to 320 pixels before saving. Visible timeline and word images use the bounded thumbnail cache, and video playback starts only when a post is opened; its temporary playback file is written off the main UI thread. Individual moment files cap input at 24 MB and encode or decode off the main UI thread; their importer reads only up to the cap plus one byte on a background task. Fourteen focused note tests passed, including lazy load, profile and backup isolation, media and turn limits, prepared video, picture words, and conversation turns surviving relaunch and backup, file exchange with fresh identifiers, and backdated timeline order. iPad UI tests created, exported, and reopened a captioned moment; opened a video post's player; created, spoke, and reopened a picture-word moment; and added communicator and partner turns that survived relaunch. Physical-device timing with a full notebook remains unmeasured.

ARASAAC pictogram downloads now resize image data on the existing background ImageIO path, avoiding synchronous image preparation in the search view. The new Save to Photos action checks add-only authorization before downloading and writes its prepared picture through PhotoKit. A focused iPad UI test saved a live ARASAAC result and received the success message; the two ARASAAC unit tests passed. An initial UI run exposed a Swift 6 actor-isolation crash in PhotoKit's change block; explicitly marking that block sendable resolved it in the rerun. The Release build installed and rendered the Speak board on the available iPad Pro 11-inch (M4) iOS 27 simulator after a CoreSimulator reboot. These checks verify the save flow and remove main-thread image preparation, but do not quantify a search-screen speedup or normal-user startup time.

Backup import previews now read and decode selected JSON files on a background task while showing a Reading backup indicator. The preview retains only board names and button counts alongside the raw backup data, instead of holding a second decoded profile with its media in memory. Button counts are accumulated in one pass instead of filtering every item for each board row. Opening a local snapshot uses the same background preview path and avoids its former redundant validation decode; the separate export path still validates local backup files. The preview-summary and local-backup unit tests passed, including rejection of corrupt snapshot data, and the local selected-board UI flow passed on the current iPad simulator. The Release build installed, launched, and rendered the Speak board there. The external Files picker path was not exercised by UI automation. Full backup restore and backup export still perform some work on the main actor, so this change does not establish a whole-backup operation latency target.

The sensory canvas now runs its 30 fps timeline and one-second cleanup timer only while animated ripples exist. Its idle and still-circle states use a static Canvas, so leaving the page open without activity no longer schedules animation frames. The focused iPad UI flow passed through touch, turning motion off, still circles, clearing, and return navigation after a simulator reboot. An earlier attempt stalled in XCTest's idle wait even though a process sample found the app main thread idle; no idle battery or frame-rate measurement was taken.

Next startup check: measure first usable communication action on an unlocked physical iPad in a Release build, then profile any delay that exceeds the simulator's framework-startup baseline. Use `xcrun simctl list devices available` to select a current simulator when repeating tests.
